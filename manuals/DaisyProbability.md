## 二、开篇《64 块钱，怎么分》——帕斯卡的分金问题

姐姐妹妹掷硬币赌钱，各出 **32 块**（共 64），**先到 3 分**者全拿。打到 **2 比 1** 妈妈喊停。**钱怎么分？**

先摆三种听着都有理的错答案（全给领先的／对半／按 2 比 1 分得 42 块多——**最后这个历史上真被当过标准答案**）。然后是帕斯卡 1654 年那一句：

> **已经打完的那三局，一分钱也不值。值钱的是还没打的那几局。**

姐姐差 1 分、妹妹差 2 分 → 最多再打两局 → **把两局补完**，四条路，姐姐赢三条 → **48 比 16**。

**这一篇真正的载荷是那个"奇怪的动作"**（绿盒，全册的种子）：

> **有些局根本不会打**（姐姐赢了第一局就结束了），**可我们还是把它补上了**——
> **因为只有两局都补满，四条路才一样可能。**
> **把不会发生的也补上，好让所有结局一样可能。**

它在**第三篇**长成"结果单"，在**第五篇**被追问"凭什么一样可能"，在**第十一篇**和贝特朗那三种拆法并排结账。

**为什么它比贝特朗更适合开篇**（写给以后还想动结构的人）：贝特朗是**病理学案例**，示范的是"这样问不行"；分金是**建设性**的，示范的是"这门学问怎么起步"。而且分金**一上来问的就是"值多少钱"**，和第八篇的公平价直接连着，比"可能性"更贴近孩子——**分钱**。

**开篇还有一件事**：让姐妹俩**从 2 比 1 开始真重打 40 遍**，姐姐赢 **31 遍**（0.775），算出来 0.75。**接近但不一样**——第二问就这么长出来，第九篇回答。

**三个问题（行程单）**：①凭什么"一样可能"（→ 一、三、五篇，并点出"不是什么事都能摆成几条路来数"，引向圆）；②数出来的次数凭什么就是可能性（→ 九篇）；③"值多少钱"怎么算（→ 八篇重算 48 块、十篇加消息）。

**主线装置有两条，盒题各自 grep 可点数**：
- 「**回头望一眼那个圆**」——第三、五、八、九、十篇 ＋ 第十一篇收官；
- 「**回头望一眼那 64 块钱**」——开篇立、**第八篇**用公平价重算 48 块（并加一个"输家领 16 块安慰奖"的变种，得 52 块，说明**结果单没变、变的是翻译机**）、**第十一篇**结账。

## 四、绝不能动的三样

沿用前三册的三条铁律，本册的具体形式：

**1. 妹妹出招，姐姐接招——本册形式是"打赌"。**

## 五、这一册特有的设计判断

**① 测度论绕得过去，而且必须绕。**
Bertrand 悖论**不需要**测度论来解释——它需要的只是"你得先说清楚怎么取"。所以：**全册在有限世界里把概率空间、期望、条件期望统统讲完**；圆是唯一的连续对象，用"长度比／面积比"处理。σ-代数、不可测集**只进灰盒当传说**——沿用第一册"不可测集只能当传说、正文用零公理平替"那次的定案（那次用户判过"过重"并回滚，别重蹈）。

**② 连续情形只做均匀。**一段上的均匀、圆周上的均匀、圆面上的均匀，就这三样。任何"密度函数"都不出现。面积的可加性**是借来的**（第二册第八篇做过面积），附录 D 记账。

**③ 期望是一台老实机器——这是四册之间第一次三向回响。**
第三册讲过"老实机器"（能拼、能乘倍数）。**期望正好是一台老实机器**：把两个赌局合起来的公平价，等于两份公平价相加；赌注翻三倍，公平价也翻三倍。而且**加法这一条不需要两者独立**——这是最反直觉又最有用的一条。**第八篇**直接还第三册的账，写明"这就是那两条家规"。

**④ 等可能是假设，不是定理**（**第五篇**）——它是全册的枢纽，因为它正是贝特朗的病根。骰子六面等可能，靠的是**对称**这个假定；圆上"均匀"却有三种不同的对称可讲，于是三种答案。**第五篇讲不透，第十一篇就结不了案。**

**⑤ 条件概率先于条件期望，且中间必须隔着期望与大数定律。**第七篇（条件概率）到第十篇（条件期望）之间隔着八、九两篇不是拖沓：孩子得先把"期望＝公平价"坐实，"知道消息以后的新公平价"才有东西可改。

**⑥ 尾声是"门缝"，不是第十二篇；它的轴是「账本＝测度」（08-02 用户改定的核心逻辑，动它前先读）。**正文十一篇在有限世界里自洽收官，尾声只把门推开一条缝——所以它**不占篇号、不进附录 C 习题总表**（与开篇对称，留题用盒子）。

**核心逻辑（用户 08-02 原话）：**"测度论对概率论的意义是，我们从来不能指望能精确的判断下一次掷出的骰子是哪个点，但是针对骰子的各种各样组合（掷两个骰子，各是什么，加起来是什么，加起来小于什么等等），我们都能判断其可能性，这使得各种复杂赌局成为可能。账本这个比喻很好，可以当成测度。"

**为什么这一版比初稿对**（初稿把测度论的入场理由挂在"每个点的份是 0、加不出半段"上）：那是**病理学式**的理由——出了毛病才请测度论救火。而本册开篇之所以从贝特朗换成分金，判据正是"**贝特朗是病理学案例，分金是建设性的**"（见 §二）。尾声原来犯的正是被开篇改掉的那个毛病。新核心是建设性的：**账全 → 复杂赌局才成立**。接口也是现成的——**第四篇第一节开头本来就写着"我们关心的从来不是单个结果"**，尾声把这句话推到底。

**六节的弧（账本的五问）**：§一 **有多大**（36 格表；每种圈法就是一个问题，圈法有六百八十七亿多种；账本＝测度，Durrett 那句名言归到这里）→ §二 **撑不撑得住写不完的单子**（无穷结果单，份 0 的行；撑住了）→ §三 **撑不撑得住连续**（造点机器；点撑不住，只好只记段不记点；勒贝格／Borel／σ-代数归这里）→ §四 **能干什么**（翻倍下注＝复杂赌局的活例子，公平价咬死 0；分金价钱树；鞅）→ §五 **消息来了怎么更新**（条件独立、马尔可夫）→ §六 收官。**"叠加要跟得上"这一条的落点变了**：它在 §一 先以"有限世界里白送"的面目出现，到 §三 才"要靠本事挣"——原来它是孤立的会师点，现在是这条弧的一环。用户点名的"鞅＋条件独立交叉点"那句仍在，**降为 §六 的收尾**，不再当组织框架。

守线三条不变：**不可测集一个字不提**（第一册"过重"回滚的教训）；无穷只以第一册部分和／"要多小有多小"的方式进场（借条全在附录 D）；正文十一篇只动指针、一字未改论证（改核心逻辑这一轮只在第四篇第一节加了一句指针）。**分金公平价树仍是尾声最值钱的一段**：它让开篇的分法第一次有了"在哪儿喊停都公平"的完整理由，也让塔性质有了动态的样子。

### 交叉引用语义对账（`audit_refs.py`）

`python3 audit_refs.py --vol vol4`。**它是给人过目的工具，不是闸。**

- **基线对差要按"记录"比、不能按行比**——一条嫌疑是**多行**的（`✗/⚠` 抬头 ＋ 缩进明细）。做法：先把每条合并成一行（抬头去掉 `:行号`，用 ` | ` 接上明细），再比计数。**行号不去掉就是假警报**：你在正文插几行，所有下游嫌疑的行号全变，`comm` 会把它们当"新增"报给你。顺带：**BSD sed 不认 `\+`，必须 `-E`**（用 `\+` 会静静地什么都不替换，假警报照旧）。
- **引号里的句子会被当成"对被引处的承诺"，加粗一律不算。**所以固定动作是：**逐字引用才用引号，自己换的说法一律用加粗**。本册 08-02 一晚上在这上头被抓了 4 处（"知道了现在，过去就多余"等），全靠改成加粗解决，一次正文都没动。**教训升级：篇引用同一句话里干脆一个引号都别用**（灰盒里"一件事"带引号紧邻第四篇引用，被拼成了怪承诺串）。
- **[3.96] 搬家哨兵按"邻近"配对**，同一个盒子里别处的篇引用会被拉来配你的公式串。遇到就**改文字、不动闸**——一条闸为了排版上的方便被放松一次，下次就拦不住真的悬空。

> **⚠ `audit_refs.py` 的 `VOLS`／`VOLNAME`／`NAME2VOL` 三张表必须有 vol4。**08-02 漏过一次：跑 `--vol vol4` 打印"**扫了 0 处引用**"，看着像"干干净净零嫌疑"，**其实是它压根不认识这一册**。**判据：打出 0 处就是没接上，不是没问题**（本册正常应扫到约 194 处）。

### 节号对账（`audit_sections.py`，08-03 加，**是闸，不过就中止**）

`audit_refs` 的盲区正下方还有一块：**引用的节号指错了，可被引的那个词是加粗的**——"引号＝承诺"那套查不到它。于是有了这道闸，已接进 `publish.sh`，每册构建后跑，不过就中止。

```bash
python3 audit_sections.py --vol vol4      # 不带 --vol 是四册；-v 连 ok 也打印
```

两道检查：**[S1] 存在性**（指到的篇、节在不在）；**[S2] 走错门**——紧挨着引用的那个加粗词，**在目标篇里找得到、却不在你指的那一节**。跨册引用（"第一册第二篇第三节"）本脚本不管，前面紧挨着"册"字的一律跳过。

> **⚠ 但你要知道这道闸对第四册几乎是空跑。**实测：`vol4/content/` 里「第X篇」字样共 **203 处，其中只有 5 处带节号**——而且全是同一个「第三篇第三节」。所以它每次都"通过（5 处引用）"，**这个绿灯几乎不含信息量**。
> **本册真正的风险全在它管不着的那一类上：不带节号的「第X篇」预告式引用**（"第X篇已经……／第X篇会……"）。[3.9] 不管（没节号）、[3.96] 不管（旁边没公式串）、`audit_refs` 不管（没引号）、`audit_sections` 不管（没节号）——**四道闸一道都查不到**，写的时候许下的愿，兑现不了也不会有任何东西响。
> **规矩：写下任何"某篇已经……／某篇会……"的预告，当场去那一篇 grep 一次**；反过来，新写一段内容时也想想有没有别处早就替它许过愿。**08-02 大改就是栽在这一类上**（见上面第 7 条：三处内容跨篇搬家，改号脚本只会把"第一篇"变成"第三篇"，节号和落点它管不了；"开篇"两个字也重新指了 17 处）。

### 工程侧血泪教训

- **每一张图都要亲眼看过。**前三册有九张图第一版是坏的（标签叠字、切线被横轴吃掉、端点空实心和正文对不上），全靠逐张看图发现。**图是给孩子看的，不是给脚本看的。**
- **`figs.py` 里中文用 Hiragino Sans GB、数学走 mathtext，两者绝不混在同一个字符串里**；**中文字体缺 U+2212**，图里的减号要用"减"字或 ASCII 连字符，否则渲成豆腐块。中文字体也**没有 ✓ ✗ 的字形**，要用线条画。
- **`axes()` 助手把纵轴说明放在左上角**，正文说明别放 y > 0.85×ymax（这个坑踩过三次）；两边都有负值的图用 `axes_signed()`。**两行说明别靠眼估纵坐标堆**，用一个字符串加 `\n` ＋ `linespacing`。
- **粗体不能跨 `//`。**盒子里写成 `**……// ……**`，两个 `//` 段各自都不配对，[1] 当场 FAIL。**一个 `//` 段落里自己开、自己闭。**
- **分数标记内部是 mathtext**：上标写 `^{n}` 不是 `^n^`；下标写 `_{n}` 不是 `~n~`（会**静默**渲染成一个空格）；不要全角 ＋ 或 U+2212；根号写 `\sqrt{}`。→ [3.98] 管这条。
- **竖线撞车**：表格用 `|` 分列，`[[1|2^n]]` 里也有 `|`，拆列前必须先保护 `[[…]]`。**手册本身也是 markdown 表格，往篇表格里写 `|h|` 这种绝对值会把单元格劈开**（08-03 在 DaisyCalculus 上真踩到，改用"h 的绝对值"）。
- **CENTER 里别把汉字和符号用 ＝ 接起来。**本册踩过："份 ＝ 长度"触发 [3.95] FAIL，改成纯中文句式。两条出路：**先给那个量命名再写公式**，或**整句写成句子、不带关系符**。
- **手工修补必然被下一次重跑吃掉。凡是脚本会重跑的地方，修复必须做成机制**（前三册的附录读音栏被转换脚本吃过两次，第二次才做成 `{{}}` 转义）。
- **检查失败不一定是产物错了，也可能是检查过期了。先判断哪一边过期**（前三册的 3 : 1 就是实例）。同理，**检查不能写死文件名**——写死了换一册就静悄悄空转，"零悬空"是假通过。
- **加了新脚本，记得回 `publish.sh` 的 `FILES=(…)` 加一行。**打包照样"成功"、件数照样点得齐，**交付出去的源码包却缺工具**——`tar` 不会因为你没列某个文件而报错。**判据：包内件数变了没有。**
- **zsh 不做无引号变量分词**（`set -- $f` 不生效），而且 `cmd && cd ..` 会因前一步失败而短路。
- **校验不过就不许上传。**正确写法是 `if python3 verify_docx.py vol4 >/dev/null; then <上传>; fi`——用 `&&` 接 `grep` 出过事故（`grep` 成功让 `&&` 继续执行了上传）。`publish.sh` 已经把这条做成机制。

## 十一、怎么和用户共事

- 他要的是**一起设计**。大结构先给方案，拿到"OK/可以"再动手；阶段性成果发单向汇报，不停等。
- 他会问很尖的具体问题。**先去查，不要先辩解。**查出来是错就认，改掉，并**尽量把它变成一条能自动失败的检查**——"用户指出一个具体错误 → 修 → 做成检查 → 检查立刻再抓出同类的"，这个循环在前三册跑了五轮。
- 他改方向时改得很彻底。**不要心疼已写的内容**，按新方向重做。
- 汇报时**先说没做到的、没验的、最可能出错的**，再说做了什么。
- **他随口用的大学术语，不等于要写进书里**（08-02 他说"无理数次方"，而"无理数"正是第一册明令回避的词——照办意图、换掉词，并在汇报里说一声）。
- **排版不归你验，用户自己看**（分页、盒子底色、分数垂直位置）。**每次交付仍要明说这一项没验**，别含糊过去。本机没有 LibreOffice，`--headless` 渲 PDF 是死路，别再试。
- 每一轮结尾给一条**具体的减负建议**（"如果读着还是重，最容易切的是 X，因为它不伤主线"）——用户多次据此做决定。
